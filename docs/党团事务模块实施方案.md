## 2. 当前仓库现状

### 2.1 已具备的基础

当前仓库已经具备党团事务模块的主要骨架：

- 已区分学生端和管理端路由
- 已存在党团事务页面模板骨架
- 已存在用户角色模型和权限 mixin
- 已存在较完整的党团事务核心数据模型
- 已有党团事务专项设计文档

当前 `apps/party/models.py` 中已定义如下核心实体：

- `PartyMemberStatus`：学生党团发展主档案
- `PartyStageDefinition`：标准流程节点定义
- `PartyMaterialType`：材料类型定义
- `PartyStageMaterialRequirement`：节点材料要求
- `PartyStageInstance`：学生节点实例
- `PartyMaterialSubmission`：学生材料提交记录
- `PartyApprovalTask`：审批任务
- `PartyApprovalAction`：审批动作记录
- `PartyReminder`：提醒任务

### 2.2 当前主要缺口

当前模块已经完成“最小可运行闭环”，但与完整需求相比仍存在以下明显缺口：

- 管理端工作台仍偏演示型，数据面板密度和联动性还不够
- 提醒机制已能通过命令运行，但尚未完成计划任务接管与失败重试
- `track_type=league` 仍主要停留在模型预留，尚未形成完整业务闭环
- 文档、部署说明与交付材料仍需继续整理

## 3. 本阶段总目标

本阶段建议总目标为：

在现有 Django 模板项目结构下，完成一个可运行、可演示、可持续迭代的党团事务最小闭环系统。

最小闭环至少应支持：

1. 学生登录后查看个人党团流程进度
2. 学生查看当前节点、时间线和材料要求
3. 学生上传材料并提交审批
4. 管理员查看待审批任务
5. 管理员执行通过或驳回
6. 系统记录审批动作并更新流程状态

## 4. 范围控制

为了降低实现风险，本轮开发范围建议控制如下：

## 5. 统一业务主线

建议全组统一围绕以下业务主线开发：

1. 学生具有一份 `PartyMemberStatus`
2. 系统根据 `PartyStageDefinition` 定义流程阶段
3. 学生在每个阶段拥有 `PartyStageInstance`
4. 阶段可配置必交材料要求
5. 学生上传材料后形成 `PartyMaterialSubmission`
6. 学生发起审批后创建 `PartyApprovalTask`
7. 管理员审批后生成 `PartyApprovalAction`
8. 审批结果驱动当前阶段更新，并决定是否推进到下一阶段

## 7. 建议代码组织

建议 `apps/party` 模块后续逐步组织为：

```text
apps/party/
  admin.py
  apps.py
  forms.py
  models.py
  selectors.py
  urls.py
  urls_admin.py
  urls_student.py
  views.py
  services/
    __init__.py
    workflow.py
    approval.py
    reminder.py
```

职责建议如下：

- `models.py`：持久化模型
- `forms.py`：上传、审批、筛选相关表单
- `selectors.py`：复杂查询封装
- `services/workflow.py`：流程推进相关逻辑
- `services/approval.py`：审批相关逻辑
- `services/reminder.py`：提醒生成和检查
- `views.py`：薄视图，仅负责调度与渲染

## 9. 前端实施建议

本项目现阶段建议继续遵循以下前端策略：

- 使用 Django Template
- 使用现有 `base.html`
- 使用现有 `static/css/main.css` 体系
- 保持“校园政务风格、红色主题、卡片式结构”
- 学生端偏移动端友好
- 管理端偏 PC 列表与表格

建议优先级如下：

1. 先让页面展示真实数据
2. 再补交互和表单
3. 最后统一视觉和细节优化

## 10. 团队统一约定

后续开发团队应统一遵守以下原则：

1. 用户、角色、权限逻辑统一以 `apps/users` 为基线
2. 党团事务流程模型统一以 `apps/party/models.py` 为基线
3. 页面权限控制统一使用 `LoginRequiredMixin` 和 `RoleRequiredMixin`
4. 业务规则不直接写在模板中
5. 流程流转和审批规则尽量放入服务层
6. 模板尽量只负责展示，不承担复杂业务判断
7. 新增页面和样式应尽量复用现有模板和 CSS 变量体系
