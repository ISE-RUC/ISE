# 智能问答（QA）模块开发计划（RAG + 输出管理）

适用项目：学院党团事务管理系统（ISE）  
模块负责人：智能问答模块（你负责）  
技术路线：RAG（检索增强生成）+ 输出管理（可控回答结构/引用/兜底）  
代码框架：Django 4.2（项目已集成）  

---

## 1. 目标与边界

### 1.1 目标（必须达成）

- 面向学院党团相关咨询场景，提供“可追溯、有依据、风格统一”的问答服务
- 支持将学院党团流程文档纳入知识库，形成可检索的结构化内容
- 输出回答具备：引用来源、关键信息结构化、无法确定时的明确兜底
- 与现有前端风格一致（卡片、主题色中国红、统一圆角/阴影、避免内联样式）

### 1.2 边界（一期不做或不强制）

- 不强制接入真实大模型在线 API（可先以“检索 + 模板化摘要/摘录”打通全链路，再替换为生成式回答）
- 不强制做复杂的对话记忆与多轮推理（先做单轮问答 + 轻量上下文）
- 不强制做用户画像强个性化（可做权限与角色差异化的基础规则）

## 3. 总体架构设计

### 3.1 模块位置与工程约束

- Django app：`apps/qa/`
- 页面模板：`templates/qa/`
- 静态样式：统一使用 `static/css/main.css` 中的类与变量
- 路由：`/qa/` 已接入 `apps.qa.urls`

### 3.2 端到端流程（单轮问答）

1. 用户输入问题（可携带角色：学生/团支书/辅导员等）
2. 输入规范化（去空、长度限制、敏感词/越权意图初筛）
3. 检索阶段（RAG 的 R）
   - 候选召回：向量检索 + 关键词检索（可二选一，建议最终双路融合）
   - 重排（可选）：对 TopK 片段做相似度重排或规则重排
4. 构造上下文（把最相关片段拼成“可引用上下文”，并带来源元信息）
5. 生成/组织答案（RAG 的 G）
   - 早期可用“模板化回答（抽取/拼接）”快速上线
   - 后期替换为大模型生成（本地/在线皆可）
6. 输出管理（必须）
   - 非党团，学业相关问题不回答
   - 对问题进行分类（入党、团员关系转接、发展对象材料、党团组织生活、评优评先等流程）
   - 对每类问题统一回答结构（结论 → 步骤 → 材料清单 → 注意事项 → 引用）
   - 置信度与兜底策略（无法确认时明确说明、引导线下咨询或提供入口）
7. 返回页面展示（答案、引用、相似问题、反馈按钮）

## 4. 知识库建设计划（RAG 的核心）

### 4.1 数据范围（建议优先级）

- 党团流程类：入党流程、团员关系转接、发展对象材料、党团组织生活、评优评先等
- 规章制度类：学院/学校相关管理办法、通知公告中的流程规则
- 表单与材料类：申请表、证明材料清单、模板下载说明

### 4.2 数据形态与处理策略

项目已包含 `python-docx`，适合优先纳入 `.docx` 文档；PDF 建议补充解析依赖后再纳入。

- 文档接入优先级：
  - 优先：DOCX（解析稳定、结构清晰）
  - 其次：HTML/Markdown（若学院已有网页/说明）
  - 再次：PDF（需引入解析库并验证可用性）

### 4.3 文档清洗与结构化

目标是把“流程”拆成可检索的片段，并保留“引用”所需的元数据。

- 元数据字段（建议最小集合）
  - `source_id`：文档唯一 ID
  - `source_title`：文档标题
  - `source_type`：docx/pdf/html/md
  - `source_path`：原始文件路径或上传后的存储路径
  - `section`：章节/小节名（若能解析）
  - `updated_at`：更新时间
- 片段策略（chunking）
  - 以“流程步骤/小节/条款”为基本单位切分
  - 每段控制在 200～500 字为主（便于检索与引用）
  - 必要时使用“重叠窗口”减少信息断裂（如步骤说明跨段）

### 4.4 版本与审核机制（建议）

- 每次入库生成一次“索引版本号”
- 支持标记“已废止/被替代”的文档，避免旧流程误答
- 知识条目支持人工审核状态：草稿/已审核/已下线

## 5. 检索方案（RAG 的 R）

### 5.1 方案 A：关键词检索（零依赖起步，最快可用）

适合在不引入额外依赖的前提下先跑通闭环。

- 实现方式
  - SQLite + LIKE/简单倒排（最简）
  - 或后续迁移到 PostgreSQL（`psycopg2-binary` 已在依赖中）并使用全文检索
- 优点
  - 依赖少、上线快、可解释
- 缺点
  - 对同义表达、口语问题召回弱

### 5.2 方案 B：向量检索（RAG 标配，效果更稳）

建议作为正式版本目标。

- 需要补充的依赖（建议写入 `requirements.txt` 并锁定版本）
  - `sentence-transformers`：文本向量化（可离线）
  - `faiss-cpu` 或 `chromadb`：向量索引与检索
  - `pdfminer.six`：PDF 文本抽取（若要入库 PDF）
- 关键设计点
  - embedding 模型选择：优先中文表现稳定的通用模型
  - TopK：初期可取 5～8，后续用评测集调参
  - 相似度阈值：低于阈值则走兜底，不强答

### 5.3 双路融合（推荐的最终形态）

- 召回：关键词召回一批 + 向量召回一批
- 合并去重：按 `source_id + section + chunk_id` 去重
- 重排：按相似度/关键词命中/文档审核状态/更新时间加权排序

## 6. 输出管理（回答可控与可验收的关键）

### 6.1 统一回答结构（建议强制）

回答内容固定分区，便于用户快速执行，也便于验收：

- 结论（1～2 句直接回答）
- 办理步骤（编号列表，避免长段落）
- 所需材料（清单）
- 办理地点/渠道（如党支部/学院党委办公室/线上入口）
- 注意事项（时间节点、易错点、例外情况）
- 依据与引用（必须：列出来源标题 + 小节/片段摘要）

### 6.2 置信度与兜底策略

- 命中不足：检索相似度低或 TopK 内容冲突 → 明确说明“不确定”，并提供：
  - 建议咨询渠道（例如：辅导员/组织员/党支部）
  - 可执行的下一步（需要补充哪些信息、去哪个页面提交）
- 越权问题：如索要他人隐私、敏感信息 → 拒答并解释原因
- 时效性问题：对“截止时间/最新政策” → 强制提示以最新通知为准，并给出通知中心入口

### 6.3 引用展示规范

- 引用至少包含：文档标题、章节（若有）、入库时间/版本号
- 引用片段尽量短（1～3 句），避免整段堆砌

## 7. Django 侧实现计划（页面、接口、任务）

### 7.1 页面与交互（建议一期）

页面建议沿用现有“卡片 + 输入框 + 主按钮”风格（见 `static/css/main.css` 的 `.card`、`.search-row`、`.btn`）。

- `/qa/`：智能问答主页面
  - 输入框 + 提交按钮
  - 答案区域（卡片）
  - 引用区域（折叠或列表）
  - 相似问题推荐（可选）
  - 反馈按钮：有用/无用 + 问题分类（可选）

### 7.2 接口与视图（建议拆分）

建议把“展示页面”和“回答接口”分开，便于后续做异步/前后端分离。

- 页面视图
  - `IndexView`：渲染 `qa/index.html`
- API（建议用 DRF，项目已依赖 `djangorestframework`）
  - `POST /qa/api/ask`：提交问题，返回回答、引用、置信度、相似问题
  - `POST /qa/api/feedback`：记录反馈（可选）

### 7.3 模型与数据表（建议最小集合）

一期最小可落地（可先 SQLite，后续换 PostgreSQL）：

- `KnowledgeSource`：知识来源（文档）
- `KnowledgeChunk`：知识片段（可检索单元）
- `QaSession` / `QaLog`：问答日志（问题、回答、引用、用户、时间、置信度）
- `QaFeedback`：反馈（有用/无用、原因标签）

如果一期为了快速上线也可以暂时不建表，先用本地文件索引；但为了可验收与可追溯，建议尽早落表。

### 7.4 入库与索引构建（建议做成管理命令）

建议实现 Django 管理命令，形成可重复执行的数据流水线：

- `python manage.py qa_ingest --path <docs_dir>`
  - 扫描 DOCX/PDF/MD
  - 抽取文本与章节
  - 切分 chunk + 写入数据库
  - 构建/更新索引（关键词索引或向量索引）
- `python manage.py qa_reindex`
  - 重新计算 embedding / 重建索引（当模型或切分策略更新时）

## 8. 评测与验收（保证“可行且可证明”）

### 8.1 评测集建设

- 从学院真实场景整理 50～100 条问题
  - 直接问流程：如何入党、需要哪些材料、什么时候交
  - 模糊口语：入党要怎么搞、团关系怎么转
  - 反问/多意图：我想入党又要转团关系怎么办
  - 负例：索要他人信息、与党团无关的问题
- 每条问题配“参考答案要点”与“必须引用的来源”

### 8.2 核心指标（建议验收口径）

- 可用性：能回答覆盖率（命中并输出结构化步骤的比例）
- 可追溯性：回答引用覆盖率（回答包含引用且引用正确）
- 稳定性：相同问题多次输出结构一致、无明显矛盾
- 兜底质量：无命中时能给出合理下一步，不编造

### 8.3 人工验收流程（建议）

- 组织员/辅导员抽查 Top 20 高频问题
- 对“错误或有风险”的条目回流：修正文档、标记废止、补充规则

---

## 9. 风险与对策

- 文档不一致/过期：建立版本与“废止”标记；回答中提示以最新通知为准
- PDF 解析质量差：优先 DOCX；PDF 入库前做抽样对比
- 召回不足导致乱答：设置相似度阈值与强兜底，不强行回答
- 输出不稳定：使用固定回答结构与模板，逐步引入生成能力
- 隐私/越权：加角色与权限规则，记录审计日志

## 10. 里程碑交付清单（按“可运行闭环”排序）

### 10.1 M1：跑通闭环（不依赖大模型）

- 知识库：DOCX 入库 + chunk 存储
- 检索：关键词检索
- 页面：`/qa/` 可提问并返回“基于片段的结构化回答”
- 引用：展示来源文档与片段
- 兜底：无命中时引导用户补充信息/跳转通知中心

### 10.2 M2：效果增强（向量检索 + 融合）

- 向量检索（embedding + TopK）
- 双路融合 + 重排
- 评测集与指标统计（至少覆盖常见问题）

### 10.3 M3：生成式回答（可选）

- 在 M2 的“引用上下文”基础上加入生成模块
- 输出管理升级：强制引用、避免编造、结构稳定
- 安全策略与拒答策略完善
